# SPEC-0002：业务模型与 API 契约

状态：Accepted baseline。日期：2026-10-18。

## 1. 业务实体
所有实体使用稳定 ID 作为唯一标识，不得以列表位置或数组索引作为实体 ID。
- Customer：客户名称、编码、行业、联系人、电话、邮箱、状态、备注及创建/更新时间。
- Project：项目识别信息、客户关联、负责人、状态、进度、预算和起止日期等当前模型字段。
- Order：订单号、客户关联、可选项目关联、金额、状态和下单日期等当前模型字段。
- User：姓名、用户名、邮箱、部门、岗位/角色、状态、最近登录等业务资料字段。
- Dashboard：从同一模拟数据集汇总指标、状态分布、趋势和最近订单。

精确字段类型、可空性和枚举值以 src/types 与各业务模块类型定义为准。变更模型时同步更新类型、MSW、表单、详情、导出列、测试和本文档。

## 2. 关联完整性
- 项目引用客户；订单引用客户，并可选引用项目。
- 删除仍被项目/订单引用的客户必须失败并返回可理解的冲突错误。
- 删除仍被订单引用的项目必须失败并返回可理解的冲突错误。
- 详情、列表和仪表盘来自同一模拟数据集，不得维护互相矛盾的静态副本。

## 3. API 层约定
- 页面调用业务 API 模块；API 模块使用统一 Axios 客户端。
- Base URL 通过 VITE_API_BASE_URL 配置，页面不得硬编码主机地址。
- 列表响应使用统一分页类型，表达当前页项目与匹配总数。
- 查询参数通常包括 page、pageSize、keyword、sortBy、sortOrder 和业务筛选项。
- sortBy 必须在列表允许字段白名单内；sortOrder 只允许 asc 或 desc。
- 错误统一规范化，保留 HTTP 状态、业务错误码、可读消息和可用字段详情。
- API 层不负责展示 Toast/Modal。

## 4. 主要端点
- GET/POST /api/customers：查询客户列表、创建客户。
- GET/PUT/DELETE /api/customers/:id：查询、更新、删除客户。
- GET/POST /api/projects：查询项目列表、创建项目。
- GET/PUT/DELETE /api/projects/:id：查询、更新、删除项目。
- GET/POST /api/orders：查询订单列表、创建订单。
- GET/PUT/DELETE /api/orders/:id：查询、更新、删除订单。
- GET/POST /api/users：查询业务用户列表、创建用户。
- GET/PUT/DELETE /api/users/:id：查询、更新、删除业务用户。
- 仪表盘端点：GET /api/dashboard/summary?range=30d|90d|12m

如果实现包含额外的引用查询或摘要端点，应在本文件中补充，而不是由页面直接读取 mock 数据。

## 5. 列表查询语义
- page/pageSize 为正整数；不合法或超出允许范围时回退到安全默认值。
- keyword 在提交时去除首尾空白并限制最大长度。
- 筛选键和枚举值必须白名单校验；无效值不得传入业务查询。
- 纯日期使用 YYYY-MM-DD，不做时区转换；时间点使用明确时区的 ISO 8601。
- 查询条件变更、排序变更或删除导致总数变化时，应将页码规范化到有效范围。
- 列表状态详细行为以 SPEC-0003 为准。

## 6. MSW 与真实 API 兼容
MSW 应模拟真实请求/响应行为。列表参数必须影响返回结果；写操作修改同一运行时内存数据集并触发相关查询刷新。刷新后数据恢复种子状态是预期行为。未来替换真实后端时保留实体类型、分页响应、错误契约和业务 API 边界。
