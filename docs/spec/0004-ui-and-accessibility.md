# SPEC-0004：UI、交互与无障碍规范

状态：Accepted baseline。日期：2026-10-18。

## 1. 视觉系统
- 使用 Ant Design 组件与 Design Token；业务样式使用 CSS Modules 和少量全局基础样式。
- 品牌色、主题、背景、边框、文字层级和组件尺寸通过集中主题配置维护。
- 不引入 Tailwind、第二套图标库或 Storybook，除非先更新并接受相关 ADR。
- 页面标题、说明、操作区、筛选区和表格形成清晰层级；避免重复统计、过多辅助文案和无意义装饰。
- 浅色/深色主题均验证状态标签、链接、表格选中态、弹层和禁用态的可读性。

## 2. 应用壳层
- 桌面端使用吸顶的顶部一级导航，菜单分组通过下拉菜单展示。
- 全局命令面板支持 Ctrl+K / macOS ⌘K、方向键、Enter 与 Esc。
- 小于 992px 时隐藏横向导航并使用 Drawer；Drawer 中保留品牌、搜索和主题入口。
- 不提供应用内页面标签栏；品牌视觉采用蓝紫色。

## 3. CRUD 交互
- 列表作为独立页面。
- 简单创建或快速编辑可以使用 Drawer；详情和复杂/完整编辑使用独立路由。
- 独立路由的新建/编辑页使用一致的标题、表单布局、返回路径和保存反馈。
- 打开表单时清理旧表单错误和 mutation 状态；编辑时正确映射实体初始值。
- 提交期间展示 loading 并阻止重复提交；失败时保留输入并呈现错误；成功后明确反馈并关闭或导航。
- 删除、启用/停用等有副作用的动作必须明确目标、提供取消路径并展示结果。
- 字段错误映射到对应输入；未知错误不得暴露内部堆栈。

## 4. 异步状态
- Loading：合理使用 Skeleton、Spinner 或加载文案。
- Error：展示可理解的错误状态，并在可恢复时提供重试。
- Empty：解释没有数据，并在适当场景提供创建入口或调整筛选提示。
- Success：展示模拟 API 响应，不用硬编码静态卡片掩盖请求失败。

## 5. 响应式与无障碍
- 支持 Chrome、Edge、Firefox、Safari 当前及最近两个主要版本；不支持 IE。
- 桌面优先，但窄屏必须可操作；表格可横向滚动，表单和工具栏合理换行。
- 使用语义化元素、可访问名称、表单 label、键盘可操作控件、可见焦点和必要 ARIA 属性。
- 弹窗/Drawer 打开后焦点顺序合理，关闭后返回合适触发元素。
- 不只用颜色表达状态；文字与背景保持可读对比度。
- 不应让全局横向滚动成为窄屏布局常态。

## 6. 文案与日期
首期中文文案集中管理，保留国际化扩展空间但不引入完整国际化框架。纯日期格式为 YYYY-MM-DD，不做时区转换；时间点使用带时区的 ISO 8601。
