# 交付验收清单

本清单是 React Topnav Template（顶部导航管理后台） 的交付检查基线。未执行的项目不得标记为通过；仅补充文档不代表业务功能已经通过验收。

## A. 文档与范围
- [ ] README.md、AGENTS.md 与 docs/README.md 互相链接。
- [ ] 相关 SPEC、ADR 和验收项齐全且不冲突。
- [ ] 没有擅自增加真实后端、登录认证、权限系统或持久化能力。
- [ ] 没有引入另一模板仓库的代码包、workspace、submodule 或运行时依赖。
- [ ] 实现与 SPEC 不一致时，差距已明确记录并拆为后续代码任务。

## B. 工程质量
- [ ] pnpm install --frozen-lockfile 成功。
- [ ] pnpm lint 通过。
- [ ] pnpm typecheck 通过。
- [ ] pnpm test 通过。
- [ ] pnpm test:coverage 成功生成报告；首期不设全局覆盖率百分比硬门槛。
- [ ] pnpm build 成功。
- [ ] GitHub Actions 的安装、Lint、类型检查、测试、覆盖率与生产构建全部成功。

## C. 页面与交互
- [ ] 仪表盘、客户、项目、订单、用户页面可在 MSW 模拟环境中完成主要操作。
- [ ] 页面覆盖加载、错误、重试与空数据状态；没有死按钮或未说明的空白页。
- [ ] 新建/编辑表单有校验、提交状态和错误反馈；字段错误能定位到相应输入。
- [ ] 删除及启用/停用等危险操作有明确确认和结果反馈。
- [ ] 客户、项目引用完整性规则在 API 和 UI 两端均可验证。
- [ ] 浅色/深色主题下文字、边框、状态标签、表格和弹层均可辨识。
- [ ] 桌面、平板和窄屏布局可操作；导航在规定断点切换。
- [ ] 语义化控件、键盘操作、可见焦点、标签和必要 ARIA 属性符合基本无障碍要求。

## D. 列表与 DataTable（必须通过）
- [ ] 搜索词和筛选控件先作为草稿；未提交时不得改变 URL 中已提交条件，也不得触发新的列表查询。
- [ ] 点击“查询”或在搜索框按 Enter 后，关键词与所有筛选一次性提交，页码重置到第一页。
- [ ] 点击“重置”恢复默认查询条件并重新查询。
- [ ] URL 只保存已提交的搜索/筛选值；排序、分页与页大小按规范同步 URL。
- [ ] 刷新、复制链接、前进/后退能恢复已提交列表状态；非法参数安全回退。
- [ ] DataTable 显式配置稳定、唯一的 rowKey 字段或提取函数；不得使用数组索引。
- [ ] 当前页选择与跨分页选择可按业务配置；批量操作明确操作范围。
- [ ] 跨分页选择使用稳定 key 保留；批量操作使用的行数据与 key 一致。
- [ ] 排序字段受白名单约束；服务端分页不只对当前页本地排序。
- [ ] 列显隐、三档密度、分页、空状态、加载状态和错误重试均可用。
- [ ] CSV/XLSX 可导出全部匹配结果，也可按明确范围导出选中行。

## E. 模拟数据与接口
- [ ] 列表、详情、表单和仪表盘使用一致的内存数据集。
- [ ] CRUD 后相关 Query 缓存得到正确更新或失效。
- [ ] 刷新后模拟数据恢复种子状态；不写入 localStorage、IndexedDB 或真实服务端。
- [ ] API 参数校验、分页、筛选、排序、唯一性和引用约束均有测试。
- [ ] CSV 中文编码/转义、日期/金额格式及 XLSX 输出均有测试。

## F. 本次文档提交的边界
本次工作仅建立正式文档体系并修正文档入口，不修改业务代码。已知差距：

- 已确认的第 95 轮决策要求筛选项与关键词一起显式提交。但当前 CustomerListPage 将筛选控件直接连接到 useListUrlState.setFilter，而该 Hook 会立即写入 URL；这与规范不一致。本次仅补文档，未改业务代码。后续应将筛选改为草稿状态，在点击“查询”或按 Enter 时一次性提交，并为所有列表补充相应测试。

差距应保留为实现待办，后续按 SPEC/ADR 修复并通过本清单；不得弱化验收条款来关闭差距。
