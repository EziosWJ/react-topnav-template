# 架构说明

状态：Accepted baseline。本文描述 React Topnav Template（顶部导航管理后台） 的分层边界，不替代具体功能 SPEC。

## 1. 系统边界
这是一个可独立启动的前端企业管理后台模板。开发环境默认通过 MSW 提供模拟 API；数据只保存在浏览器运行时内存中。当前不包含真实后端、登录认证、账号生命周期、权限控制或业务数据持久化。

两个模板在产品和交互基线上保持一致，但分别维护源码、文档、依赖与发布历史。不得通过 workspace、submodule、私有公共包或运行时依赖共享另一仓库的实现。

## 2. 技术分层
- 应用层：React、Providers、React Router Data Router、路由错误兜底和应用壳层。
- 页面与业务层：仪表盘、客户、项目、订单、用户；负责页面组合、表单、业务动作和页面级状态反馈。
- 公共组件层：PageHeader、SearchFilterBar、DataTable、StatusTag、表单容器、详情字段、导出、模拟上传及异步状态组件。
- API 层：业务 API 模块通过统一 Axios 客户端请求，不在页面中拼接 Base URL。
- 服务端状态层：TanStack Query 负责缓存、请求生命周期、失效和重新获取。
- 客户端状态层：React state 负责局部临时状态；Zustand 只用于确有必要的跨组件客户端状态。
- URL 状态层：列表已提交查询、筛选、排序和分页状态通过 URL 表达。
- 模拟层：MSW handlers 实现与页面 API 契约一致的模拟接口，数据仅驻留内存。
- 工具层：日期/金额格式化、CSV/XLSX 导出、查询参数解析、下载及主题偏好等纯工具。

## 3. 请求与数据流
页面操作 → 业务 API 函数 → 统一 Axios 客户端 → MSW（开发环境启用时）→ 模拟 handler → 内存数据集 → TanStack Query 缓存 → 页面重新渲染。

业务页面不得绕过 API 模块直接访问 MSW 数据。创建、更新或删除成功后，必须使受影响的列表、详情和仪表盘查询失效或更新。

## 4. 状态归属
- 服务端数据与请求状态：TanStack Query。
- 已提交的列表查询状态：URL query 参数。
- 未提交的搜索词和筛选项：页面/Hook 局部草稿状态。
- 表格列显隐、密度、选择等交互：DataTable 或页面状态；跨分页选择依赖稳定行标识。
- 主题和必要的全局客户端 UI 状态：按现有实现使用 Context、React state 或 Zustand。
- 禁止将服务端实体复制到 Zustand 作为第二份事实来源；禁止重复维护列表查询状态。

## 5. 错误与缓存
- API 错误在公共 API 层规范化，保留状态码、业务错误码和字段详情。
- 公共 API/组件层不自动弹出全局提示；页面、表单或具体操作负责反馈，避免重复报错。
- 4xx 请求不自动重试；可重试网络/超时/服务端查询错误最多重试一次；写入请求不自动重试。
- 查询缓存配置与 query key 集中管理；变更成功后按实体关系失效相关缓存。
- 仍被项目/订单引用的客户、仍被订单引用的项目，不得被删除。

## 6. 目录职责
- src/app/：应用 Provider、路由装配和全局错误处理。
- src/config/：环境变量、品牌、路由/菜单、选项和公共文案。
- src/layouts/：本模板专属的导航与应用壳层。
- src/components/：可复用 UI 组件。
- src/features/：客户、项目、订单、用户和仪表盘的业务 API、查询逻辑及表单组件。
- src/pages/：仪表盘、业务模块列表/详情/表单页。
- src/lib/：API 客户端、错误规范化、查询缓存和表单错误处理。
- src/hooks/、src/stores/、src/utils/、src/styles/、src/types/：Hook、客户端状态、纯工具、样式和类型。
- src/mocks/：MSW handlers、种子数据、浏览器 worker 与测试 server。
- tests/：按模块组织的单元和组件测试。
目录细节以当前仓库实际路径为准；调整目录时同步更新本文。

## 7. 配置与部署
- 环境变量统一在 src/config/env.ts 解析，业务模块不得直接读取 import.meta.env。
- API Base URL 通过 VITE_API_BASE_URL 配置，部署基路径通过 VITE_BASE_PATH 配置。
- MSW 开发环境默认启用，生产默认关闭；关闭 MSW 时须有真实 API 提供相同契约。
- 生产构建为 SPA，静态服务器需配置 history fallback；模板本身不提供真实后端、Docker 或 Nginx 部署方案。
- 不得提交真实密钥、令牌或生产数据。

## 8. 本模板布局差异
- 桌面端采用吸顶的单行三段式顶部导航：左侧品牌、中间一级导航、右侧全局搜索与主题工具。
- 一级导航使用下拉子菜单；窄屏隐藏横向菜单并通过汉堡按钮打开 Drawer。
- 全局命令面板支持按钮、Ctrl+K/macOS ⌘K 打开，支持方向键选择、Enter 跳转和 Esc 关闭。
- 不提供应用内页面标签栏。
- 宽内容区采用蓝紫色视觉基调，保留清晰的页面标题、筛选和表格层级。
